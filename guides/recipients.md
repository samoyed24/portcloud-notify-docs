# 通知渠道

在<a href="/app/channels" target="_self">通知渠道</a>管理邮箱、ntfy、企业微信、飞书与钉钉。需要 Supporter 或以上权限，参见[账号方案](./plans.md)。

## 添加邮箱

1. 选择「邮箱」，点击「添加邮箱」，输入地址，可填备注名。
2. 收取 6 位验证码，15 分钟内输入并确认。
3. 渠道显示已验证后即可发送。

关闭验证码对话框不会删除邮箱，可在有效期内继续输入。重发会替换旧码，使用最新一封。收不到时检查垃圾邮件，等倒计时结束后重发。

## 添加 ntfy

1. 选择「ntfy」，点击「添加 ntfy」，输入 topic（如 `alerts`，1–40 位字母 / 数字 / `_` / `-`，非 URL）。
2. 添加即生效，无需验证。复制列表中的完整 topic（如 `ab12cd34ef56-alerts`）。
3. 向管理员获取 ntfy 服务器地址，在该服务器上订阅完整 topic。

完整 topic 等同密码，知道即可订阅，不要公开。列表默认遮盖，用眼睛按钮查看、复制按钮复制。无效 topic 返回 `400 CHANNEL_TARGET_INVALID`。

## 添加企业微信

1. 在企业微信**内部群**右上角点击 `[...]` → `消息推送`（旧版本叫「群机器人」）→ `添加`，创建一个机器人。
2. 在机器人详情里复制 **Webhook 地址**，形如 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=<UUID>`。
3. 在控制台选择「企业微信」→「添加企业微信」，粘贴完整 Webhook 地址或其中的 UUID key，可填备注名。
4. 渠道先进入「未验证」状态。到企业微信群里读取系统发送的六位验证码，在控制台完成验证后才可发送通知、加入预设或测试。验证码 15 分钟有效，最多允许 5 次错误，成功后立即失效。列表显示 `wb_` 开头的目标标识与脱敏 key（如 `693a...5aaa`）。
5. 若发码失败，渠道仍保留在列表并占用企业微信名额。关闭对话框后可点该行「验证」，手动重发；失败或超时不代表已送达，也不会自动重试。ntfy 不需要验证码。

验证码使用独立预算：**每账号每天 5 次**；同一 Webhook 在全平台跨账号、跨渠道共享 **每 60 秒 1 次、每天 5 次**。每日按服务配置的时区日切，投递失败和超时也消耗次数，不退额度。Redis 不可用时拒绝发码，不绕过限额。此预算与正常通知发送的业务限额分离；控制台「测试通知」也必须使用已验证渠道，并遵守正常发送限额。

验证码消息是固定系统模板，不携带用户提供的备注、正文、链接或 `@`。验证只限制本平台使用：**如果真实 Webhook 已泄露，应在企业微信删除并重建机器人/更换 Webhook**，本平台验证不能阻止他人直接调用它。此前的企业微信验证升级曾把存量渠道恢复为未验证；当前版本不会重置已有企业微信渠道，新增的飞书与钉钉渠道则从添加时起就需要验证。

发送时 `to` 使用列表里的 `wb_...` 目标标识，而不是 Webhook 地址。原始 key 加密存储，接口与日志不会回显。

限制与注意事项：

- 仅支持企业微信**内部群**；包含外部联系人的外部群不能添加机器人。
- 群开启「全员禁言」时，机器人消息可能无法送达；请让群主关闭后再试。
- 每个机器人每分钟最多 **20 条**消息，超限返回上游 `45009`。
- 纯文本正文（标题 + 空行 + 正文）最多 **2048 个 UTF-8 字节**，超长会在受理前被拒绝。
- 机器人被移出群或 Webhook 失效时，上游返回 `93000`，需重新添加并更新渠道。
- 群机器人不支持 `@` 成员；本服务只发送普通文本。

## 添加飞书

1. 在飞书群设置中打开「群机器人」→「添加机器人」→「自定义机器人」，创建机器人并复制 Webhook 地址（`https://open.feishu.cn/open-apis/bot/v2/hook/...`）。国际版 Lark 使用 `open.larksuite.com`，协议相同。
2. 在控制台选择「飞书」→「添加飞书」，粘贴完整 Webhook 地址。若机器人在安全设置中启用了「签名校验」，同时填写签名密钥；未启用则留空。
3. 渠道先进入「未验证」状态。到目标群读取系统发送的六位验证码，在控制台完成验证后才可发送、加入预设或测试。
4. 发送时 `to` 使用列表里的 `fs_...` 目标标识。原始 Webhook 与签名密钥加密存储，接口只返回脱敏值。

飞书自定义机器人只能向所在群推送，不支持单聊。官方限制：整个请求体最多 **20 KB**，单机器人 **100 次/分钟、5 次/秒**。超限或系统压力可能返回 `11232`。若启用了关键词或 IP 白名单，消息内容或服务出口地址必须满足对应条件，否则上游返回 `19024` / `19022`。成功以响应 `code == 0` 为准。

## 添加钉钉

1. 在钉钉群设置中打开「机器人」→「添加机器人」→「自定义机器人」，创建机器人并复制 Webhook 地址（`https://oapi.dingtalk.com/robot/send?access_token=...`）。国际站为 `oapi.dingtalk.io`。
2. 在控制台选择「钉钉」→「添加钉钉」，粘贴完整 Webhook 地址或只粘贴 `access_token`。建议在机器人安全设置中启用「加签」并填写 `SEC...` 密钥。
3. 渠道先进入「未验证」状态。到目标群读取系统发送的六位验证码，在控制台完成验证后才可发送、加入预设或测试。
4. 发送时 `to` 使用列表里的 `dt_...` 目标标识。原始 access token 与签名密钥加密存储，接口只返回脱敏值。

钉钉自定义机器人只支持群聊，不支持单聊、已读回执或撤回。官方限制为每个机器人 **20 条/分钟**，超限会限流 10 分钟（`410100`）。成功以响应 `errcode == 0` 为准。若使用关键词或 IP 白名单而不是加签，消息内容或服务出口地址必须满足对应条件；否则验证码本身也可能被上游拒绝。

## 数量上限与删除

邮箱、ntfy、企业微信、飞书与钉钉各有独立上限（默认各 3）。邮箱只统计已验证的，其余类型统计全部（含待验证）。达到上限时删除不再使用的渠道即可释放。

删除渠道不会撤回已受理的通知。

## 在程序中核对可用地址

`GET /api/v1/emails` 返回当前账号已验证的邮箱数组，需要 API Key。只读，不能申请验证码或删除邮箱。详见[收件人 API](../api/recipients.md)。
